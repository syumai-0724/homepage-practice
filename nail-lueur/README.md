# Nail Salon Lueur — 大人女性向けネイルサロンのデモ

アイボリー・シャンパンベージュ・ゴールド・ダスティローズを使った、独立した静的サイトです。既存のカフェやsalon-nagiは編集しません。外部ライブラリ・ビルド・APIキーは不要です。

## 起動方法

Pythonが使える環境では、このフォルダーで次を実行します。

```sh
python -m http.server 8000
```

ブラウザーで `http://localhost:8000` を開きます。GitHub Pagesではリポジトリの `nail-lueur/` 以下に配置し、`main`への反映後に自動公開します。データファイルも同じ階層に置いてください。

## ページ

- index.html：メインビジュアル、コンセプト、おすすめ3メニュー、デザイン、特徴、お知らせ、予約・FAQへの案内。
- concept.html：紹介、空間・相談・デザインの方針、衛生管理の確認欄。
- menu.html：9種類の施術メニュー、カテゴリー、詳細、料金・時間、予約への引き継ぎ。
- gallery.html：6テーマの画像、絞り込み、拡大ダイアログ、お気に入り、デザインを選んだ予約。
- reservation.html：月別カレンダー、メニュー・オプション、日時、入力確認、予約デモ完了。
- faq.html：4カテゴリー20問、複数展開、検索、カテゴリーとの併用。
- access.html：未設定の店舗情報と地図のプレースホルダー。
- contact.html：入力チェック、確認、問い合わせデモ完了。

## ファイルの役割と編集

- data.js：店舗情報、メニュー、料金、時間、オプション、ギャラリー、FAQを一元管理。
- model.js：料金計算、時間計算、予約枠、日付と入力のチェック。DOM・通信に依存しないため、将来のAPI連携にも使える構成。
- app.js：ページの表示、カテゴリー切り替え、ダイアログ、フォーム操作、モバイルナビ。
- services.js：予約・問い合わせの完了処理の差し替え箇所。現在は通信を行わないデモアダプター。
- style.css：共通デザイン、各ページの配置、レスポンシブ、動きを減らす設定。
- assets/hero.webp：AI生成のメイン画像をWeb用に圧縮したもの。
- assets/designs.webp：AI生成した6デザインの画像。CSSで各領域を表示し、同じ画像の重複ダウンロードを抑える。
- assets/favicon.svg：オリジナルのLのアイコン。

### メニューの編集

`data.js` の `menus` を編集します。`price`は税込価格、`duration`は分数、`fromPrice`と`fromDuration`は「〜」の表示を管理します。全ページと予約の見積もりに同じデータを使います。

### 店舗情報

`shop`の住所・電話・営業時間・定休日・アクセス・駐車場はnull（未設定）です。住所未設定のまま無関係な実店舗の地図を表示しません。住所を確定した後に、正しい地図URLや埋め込みを確認して接続してください。

### 仮の予約ルール

店舗の正式な営業時間は未設定です。予約体験専用に10:00〜18:00・水曜休み・15分単位・90日先までの仮設定を設けています。変更は`schedule`で行います。`sampleBusy`は架空の満席例であり、店舗の実際の空き状況ではありません。

75分などのメニューと追加オプションの時間を合計し、仮の満席例や閉店をまたぐ枠は選べません。持ち込みデザインは価格・所要時間の下限目安です。オプションの金額・時間も仮設定です。

「ジェルオフのみ」には、付け替えオフを二重に選べません。予約前のメニュー・ギャラリーリンクにはメニューID・デザインIDのみを含み、個人情報をURLに載せません。

## デモと入力情報

本名・実際の連絡先は入力しないでください。「サンプル情報を入力する」ボタンがあります。

予約・問い合わせの入力は画面上でのみ扱い、通信・メール送信・決済・永続保存を行いません。確認画面の後にデモ完了を表示し、フォームと確認内容の個人情報を消去します。ページを離れるときにも個人情報の入力欄を消去します。

`services.js`には氏名・メール・電話・備考を渡しません。予約データをlocalStorage、sessionStorage、Cookie、ログへ保存する処理はありません。お気に入りだけは`sessionStorage`の`lueur-favorites-v1`にデザインIDの配列を保存します。これはブラウザーの同じタブ内のセッション用で、顧客情報を含みません。

実際の予約は成立しません。端末間での空き枠共有、本番の重複予約防止、キャンセル管理は実装対象外です。

## 画像

メインとギャラリーはこの制作のためにAI生成したデザインイメージです。実在する店舗・施術実績・顧客の写真ではなく、仕上がりを保証するものではありません。第三者サイトの写真の無断転載はしていません。

## アクセシビリティ

キーボードで使えるネイティブボタン、フォームのラベル、エラーとの関連付け、aria-expanded、aria-pressed、ライブ件数表示、スキップリンクを使用しています。拡大・確認画面はdialogで表示し、Escapeで閉じられます。FAQは初期状態ですべて閉じ、複数開けます。動きを減らす設定ではフェードや開閉アニメーションを抑制します。

## 本番運用で必要な作業

1. 店舗の実在情報、設備・衛生管理、料金、施術内容、支払い・遅刻・キャンセル規定を確認する。
2. 実際のデザイン写真の使用許諾と掲載範囲を確認して差し替える。
3. サーバー、共有DB、スタッフ認証、サーバー側の枠確保と重複制御を接続する。
4. 個人情報の扱い、保存期間、アクセス権限、通信保護を設計し、必要な案内と同意を整える。
5. サーバー側入力検証、迷惑送信対策、メール送信サービス、失敗時の対応を実装する。メール送信用の秘密情報は公開ソースに置かない。
6. デモアダプターと「デモ」の画面文言を、本番の実装を検証した後に切り替える。

FirebaseやSupabaseなどへ接続する場合も、公開クライアントだけで予約枠を確保せず、適切なサーバー処理・アクセス制御・競合処理を実装してください。

## 実装・確認結果

- 8ページのHTML構造、見出し、ラベル、リンク、画像・スクリプトの参照先を確認。
- 320・375・768・1440px幅の実ブラウザー描画で全8ページの横はみ出しを確認。
- スマホナビの開閉とEscape、メニューのカテゴリー切り替え、画像の拡大とEscape、ギャラリー絞り込み・お気に入りを確認。
- FAQ20問、初期閉じ状態、複数展開、Enter/Spaceでの開閉、カテゴリーと検索の併用、0件表示、リセットを確認。
- メニューの引き継ぎ、オフと追加時間・料金、オフのみの二重選択防止、月別カレンダー、日時選択、入力エラー、確認から戻る操作、デモ完了を確認。
- 問い合わせの入力エラー、確認、デモ完了、完了後の個人情報欄と確認内容の消去を確認。
- 予約・問い合わせでの外部要求がないこと、保存APIに個人情報が含まれないことを確認。
- コアロジックは `node tests/model.test.cjs` で再確認できます。オプション計算、75分を含む所要時間、重複する架空枠、閉店、仮定休日、90日範囲、うるう年、日本時間、入力形式、検索を検証します。

ブラウザー検証は環境のページ読み込み制限を避けるため、ローカルのHTML・CSS・画像・JSをブラウザーへ直接読み込むオフライン方式で実施しました。保存APIは検証用ストレージで確認しています。公開ドメインでの実ストレージ、実端末、Safari・Firefox等の差異は別途確認が必要です。

### 今回接続していない機能

実予約、共有データベース、実メール、決済、スタッフの管理画面は今回のデモの対象外です。店舗住所等が未設定のため、実地図・電話発信・実際の営業時間案内も未接続です。指定されたデモのページ・操作機能は省略していません。
