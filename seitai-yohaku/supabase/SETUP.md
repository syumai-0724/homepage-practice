# Supabaseのテスト接続（未実行）

今回のデフォルトは架空店舗のブラウザー保存デモです。Supabaseの契約・接続・SQL適用・本番公開はしていません。接続を行う際は、この手順を確認して許可されたテスト用プロジェクトだけを使ってください。

1. マイグレーションSQLをテスト用プロジェクトに適用します。既存の予約テーブルは変更しません。
2. Supabase Authにオーナーのテストユーザーを作ります。公開登録画面は作っていません。
3. 管理者のSQL操作で `design_tenants` に店舗を、`design_tenant_owners` にその店舗ID・実際のAuthユーザーIDを登録します。一般ユーザーは権限表を編集できません。
4. `default-design.json` のJSONを `design_documents` の `draft` と `staged` に同じ値で挿入し、店舗IDを `tenant_id` に指定します。画像は初期状態の `kind: default` で始めます。
5. `.env.example` を参考に `.env.local` へURLと公開用anon/publishableキーを設定します。service role・secretキーは禁止です。キーをGitHubに追加しないでください。
6. `npm run dev` から `/admin/design/` を開きます。Supabaseが設定されている場合は、ログインしないと設定は読めません。トークンはメモリー内だけに保持し、再読み込みで再ログインが必要です。

デザインと履歴は店舗別のテーブルに保存します。テーブルへの直接書き込みを許可せず、本人・店舗権限・データ形式・コントラスト・更新番号をチェックするRPCを使います。更新は行ロック内で行い、競合した保存は失敗させます。操作日時・ユーザーID・操作種別を監査テーブルに残します。

画像はprivateバケットへ `店舗UUID/画像UUID.webp` の形式で追加し、オーナーの署名付きURLでプレビューします。過去の画像を上書き・削除する権限は与えません。UIでは拡張子・MIME・実データの先頭・画像のデコード・画素数・容量をチェックし、CanvasでWebPへ変換します。バケットでも容量・MIMEを制限します。**直接API経由のファイル実体検査をサーバーで保証する処理は未実装です。本番では画像検証用Edge Function等を追加してからアップロードを開放してください。**

「公開を確認」はテスト用DBの `staged` を更新するシミュレーションです。匿名ユーザーへ公開するテーブル・ポリシー・ストレージは作成しません。Vercelや公開サイトへのデプロイも行いません。本番用の公開配信は、承認と別途の設計・検証後に接続します。

本番前には実際のSupabase上で、未ログイン・別店舗オーナー・期限切れトークン・直接REST/RPC・同時更新・履歴復元・ストレージのアクセス拒否を検証してください。今回の環境では実DBへの接続テストは未実施です。管理画面デモを認証済みの本物のオーナー専用管理画面として公開しないでください。
