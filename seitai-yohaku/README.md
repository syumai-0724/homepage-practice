# 整体室 余白 — トップページと予約デモ

架空の整体院の制作サンプル。既存のカフェ・美容室・ネイルサロンは変更しません。GitHubの `preview-seitai-yohaku-20261017` ブランチへ保存し、本番公開用mainには反映しません。

## 確認方法

`design-preview.zip` をダウンロードし、右クリックして「すべて展開」。展開したフォルダーの `preview.html` をダブルクリックし、「WEB予約デモへ」を押してください。予約画面だけ見る場合は `reservation.html` を開けます。2つのHTMLと `preview-app.js` は同じフォルダーに置いてください。

メニュー詳細から進むと、そのコースが予約ページで選ばれます。必要な画像・CSS・ReactをZIPに同梱しているので、インターネット接続やNode.jsは不要です。同じReactコードから生成しており、別の予約ロジックを持つプレビューではありません。

## 開発・ビルド

Node.js 22以上（制作時24）を使います。

```sh
npm ci
npm run dev
```

自分のPCで起動した場合は `http://localhost:3000`、予約ページは `http://localhost:3000/reservation/`。クラウドのlocalhostはPCからそのまま開けるURLではなく、別途ポート転送が必要です。

```sh
npm run test:booking
npm run typecheck
npm run build
npm run preview:html
```

ビルドは公開操作ではありません。`out/` に静的ファイルを書き出します。静的出力の確認には `python -m http.server 8000 --directory out` を使えます。`preview:html` はダブルクリックで確認できる2つのHTMLと共通の `preview-app.js` を生成します。

## 予約ページで実装した機能

- 3コースの選択、仮料金・施術時間の表示、トップのメニューからの引き継ぎ。
- 日本時間の月別カレンダー。過去日・水曜の仮定休日・60日先を超える日を選択不可。
- 仮の10:00〜20:00、30分単位。施術時間を考慮し、架空の予約済み時間と閉店時刻をまたぐ枠を選択不可。
- サンプルのお客様情報、入力エラー、内容確認、修正、デモ完了画面。
- 完了後の日時変更・キャンセル・キャンセル確認。変更失敗時は元の枠を保持。
- 同じ画面内のデモ予約の重複を防止。変更・取消で不要な占有を解除。
- スマホ対応、フォームラベル、エラーとの関連、キーボード、画面切り替え時のフォーカス。
- 個人情報は画面のメモリー内だけで処理。デモ完了・ページ離脱時に消去。デモ予約記録に氏名・連絡先・備考を含めない。

## ファイルの役割

- `app/page.tsx`・`components/home.tsx`：トップ、メニュー詳細・FAQ・予約ページへの導線。
- `app/reservation/page.tsx`・`components/booking.tsx`：予約画面と入力・確認・完了・変更・キャンセルの表示。
- `lib/booking-model.ts`：日本時間、日付・枠・入力値チェック。営業時間の仮ルールもここ。
- `lib/booking-service.ts`：顧客情報を受け取らない、メモリー内のデモ予約処理。本番APIへの差し替え境界。
- `lib/site-data.ts`：店舗、メニュー、料金、時間、スタッフ、FAQの仮データ。
- `app/globals.css`：配色、トップと予約のデザイン、スマホ・アニメーション軽減対応。
- `app/layout.tsx`：日本語、タイトル・説明、noindex。`next.config.ts` は現段階の静的出力設定。
- `scripts/preview-entry.tsx`・`scripts/make-preview.cjs`：同じコンポーネントからオフラインHTMLを生成。
- `tests/booking.test.cjs`：予約ルール・時間境界・重複・変更取消・入力検証のテスト。
- `public/images/studio.webp`：AI生成の空間イメージ。実在の院内や実績ではありません。
- `DESIGN.md`：全体設計と今後のサーバー・管理画面・セキュリティ実装方針。

## 未実装・デモの制限

実際の予約受付、端末間の空き枠共有、DBの永続保存、確認メール、決済、管理者ログイン・管理画面、顧客本人確認、リンクによる本番の変更・キャンセルは未実装です。

画面の完了は実際の予約確定を意味しません。空き枠は架空で、記録はページを開いている間だけ有効です。再読み込みやページ移動で消え、他の端末・タブには共有されません。同一画面内のデモ重複防止は、サーバー側のトランザクション・競合制御の代わりにはなりません。

入力する場合はサンプル情報のみを使ってください。本名・実際の連絡先・病歴などは入力しないでください。予約サービスにはメニューID・日付・時間だけを渡します。localStorage・sessionStorage・Cookieへの保存、解析・広告、個人情報の送信・ログ出力はありません。

外部サービスの契約や本番公開は行っていません。今後Supabase・メールサービス・Vercelを接続する際は承認後に進めます。静的出力設定を外し、サーバー側の入力検証・RLS・認証・競合制御・スパム対策・監査・バックアップ復元を実装・検証してから本番運用します。

## 検証

型チェックとNext.jsビルド、予約モデルのテストを実施。ChromiumのオフラインHTMLで、幅320・390・768・1280・1440px、メニュー引き継ぎ、時間制限、入力確認と修正、完了後の変更・取消、個人情報の消去を確認します。ブラウザーのローカルHTTP移動には環境側の制約があるため、プレビューHTMLを直接読み込んで検証します。

素材のAI生成表記と架空店舗表記を維持。スタッフの写真・資格・経歴・実績は未登録、住所と電話は未設定です。サンプルの営業表示は実際の営業情報を示しません。ライブラリのライセンスはZIPの `preview.LICENSE.txt` に同梱します。
