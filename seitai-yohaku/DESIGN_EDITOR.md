# オーナー向けデザイン編集 — 動作確認版

## 開き方

更新版 `design-preview.zip` を**まとめて展開**し、`design-editor.html` を開きます。`preview.html` 最下部の「店舗オーナー向け・デザイン編集を試す」からも進めます。`preview-app.js` も同じフォルダーに置いてください。

Next.jsでは `npm ci` → `npm run dev` の後、`http://localhost:3000/admin/design/` です。本番公開・デプロイは行っていません。

## 使い方

1. 架空店舗を選びます。店舗ごとに保存領域が分かれます。
2. テーマ、トップ画像・文章、セクション、レイアウトを編集します。
3. 右側のプレビューをPC・スマホ表示で見比べます。プレビュー内のリンクは誤操作防止のため操作できません。
4. **下書き保存**を押します。これだけではデモの公開状態は変わりません。
5. **公開を確認（デモ）**で確認画面を開き、**デモに反映する**を押すとテスト用の公開状態を更新します。実サイトの公開はしません。
6. 保存履歴の「下書きに復元」で以前のデザインに戻せます。復元後も、公開状態への反映は別操作です。

「公開中（デモ）」で保存前後を比較できます。未保存のまま店舗を切り替えないよう、保存または変更破棄を先に行います。デモは保存時に更新番号を確認し、検出した競合を拒否します。厳密な同時更新制御は、Supabaseの行ロックで行う構成です。

## 編集できる内容

- メイン・背景・文字・アクセントの4色。
- 3種類の書体、3種類のボタン形、3段階の余白。
- メイン画像、画像の読み上げ説明、キャッチコピー・説明文・予約ボタンの文言。
- 8ブロックの表示・非表示、上下ボタンでの並び替え、見出しと説明文。
- 標準型・写真を大きく見せる型・コンパクト型、左右配置、カードの標準／1列／2列、枠や影。
- 直近10件の保存履歴、履歴のプレビュー、下書きへの復元。

写真を大きく見せる型は文章の下に写真を置くテンプレートです。左右指定は横並びのテンプレートで使い、スマホでは読みやすい縦並びにします。住所・料金・予約処理、必須の架空店舗表記などはこのデザイン編集では変更しません。

## 現在の保存と権限

**今回の初期状態は、Supabase未接続の架空データデモです。認証済みの本物のオーナー専用画面ではありません。** この管理画面デモをそのまま本番公開しないでください。

デモのデザインは、この端末・ブラウザーのlocalStorageへ保存します。予約のお客様情報は保存しません。他の端末には同期されません。ブラウザーの設定やファイルの開き方によって保存できない場合は画面内の一時保存へ切り替え、その制限を表示します。履歴・画像を含む容量が不足したときは保存に失敗したことを表示し、現在の編集内容を保持します。

デモの公開状態は編集画面内の「公開中（デモ）」で確認できます。同一オリジンのNext.js環境ではトップページにもデモ設定を反映します。ファイルを直接開いた場合、ブラウザーによってHTML間の保存領域の共有動作が異なるため、編集画面内の比較を使ってください。

Supabase接続用コードとマイグレーションも用意しました。設定されている場合はオーナーログインを要求し、DBとprivate Storageに保存します。店舗権限の表は一般ユーザーから書き換えられず、RLSと検証付きRPCで本人・店舗・更新番号を確認します。SQLの`staged`もオーナーだけが読めるテスト状態で、匿名ユーザーへの本番公開は行いません。

実際のSupabase Auth・Storageエンドポイントとの接続は未実施です。接続の手順と本番前の確認事項は `supabase/SETUP.md` を参照してください。

## 安全性

- デザイン設定は固定スキーマ。HTML・JavaScript・自由なCSS・外部URLを入力して実行するUIはありません。
- 文言はReactの通常のテキストとして表示し、`dangerouslySetInnerHTML`は使いません。
- 色は6桁HEX、書体やレイアウトは許可リストに限定し、不明な項目・重複ブロックを拒否します。
- 文字／背景のコントラストは4.5:1以上。下回る設定は保存・反映を拒否します。ボタン文字や補助文字には読みやすい色を計算します。
- 画像はJPG・PNG・WebP、3MB以下。拡張子・MIME・署名・デコード・画素数を確認し、縮小してWebPへ再エンコードします。SVG・GIF・HTMLは受け付けません。
- プレビューはsandbox付きiframeに分離し、ユーザーの文言をiframeのHTMLとして組み立てません。
- 実DB側にもスキーマ・コントラスト・更新番号の検証を置き、直接書き込みを禁止。RPCの行ロック内で更新し、監査履歴を残します。
- 認証トークン・パスワードはlocalStorageや設定JSONに保存しません。秘密鍵は不要で、公開用キーだけを環境変数で指定します。
- 実環境の画像検査・認証運用・バックアップと本番用配信は別途検証が必要です。現段階を本番運用済みとは扱いません。

## ファイル

- `app/admin/design/page.tsx`、`components/design-editor.tsx`：オーナー編集画面とログイン・保存・確認・履歴。
- `components/design-preview.tsx`：PC／スマホの分離プレビュー。
- `components/home.tsx`：既存の各セクションを保った、設定対応の表示。
- `components/site-home.tsx`：デモ公開設定の読込と編集画面への導線。
- `lib/design-model.ts`：スキーマ、初期値、色のコントラストと安全なテーマ値。
- `lib/design-store.ts`：店舗別の架空データ保存・履歴・復元。
- `lib/design-images.ts`：画像検証・縮小・変換。
- `lib/design-supabase.ts`：Supabase認証・保存・署名付き画像の接続境界。
- `supabase/migrations/202610170001_design_editor.sql`：店舗・権限・保存RPC・監査・private Storageの定義。
- `supabase/default-design.json`、`.env.example`：初期データと公開用接続設定の例。
- `tests/design.test.cjs`、`tests/design-rls.test.cjs`：モデル・保存・画像・API境界、ローカル互換DBでのRLS確認。

## 確認コマンド

```sh
npm run test:design
npm run test:design-rls
npm run test:booking
npm run typecheck
npm run build
npm run preview:html
```

DBテストは開発用のPGliteで、Supabaseのauth・storageスキーマを最小限模したローカル検証です。未ログイン、別店舗、直接更新、権限の自己追加、形式不正、NULL値、更新競合、private画像パスを拒否することを確認します。**実際のSupabaseへの適用・Auth設定・Storageサービスの検証の代わりにはなりません。**
